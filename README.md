# baluarte

`baluarte` reads a Figma file via the Metalab MCP Figma tools, builds a structured understanding of the product (components, tokens, layouts) into a local SQLite registry, and generates a React + Storybook playground from it for design audits and dev/client handoff.

This README is for **you**, the human driver. For Claude-facing project rules, see `CLAUDE.md`.

## Pipeline at a glance

Two skills do all the work. A third (`baluarte-remember`) owns the database.

| Skill | Reads from | Writes to |
|---|---|---|
| `/baluarte-analyze <figma-url>` | Figma (via Metalab MCP only) | `.data/baluarte.db` |
| `/baluarte-build` | `.data/baluarte.db` (via `baluarte-remember`) | `baluarte-app/` |
| `baluarte-remember` | — | `.data/baluarte.db` (only skill allowed to) |

There are no `/baluarte-*` tags, comments, or annotations anymore — `analyze` walks the Figma file's artboards directly and classifies each one by name.

## Classification rule

For every top-level artboard on the file's main canvas:

- Name contains the token `screen` (kebab-segment match, case-insensitive — `home-screen`, `screen-checkout`, `Onboarding Screen`) → **layout** row.
- Otherwise → **component** row.

Nested `INSTANCE` nodes inside a component or layout are looked up and linked via `components_registry` / `layout_registry` so React composition stays honest — `<HomeScreen>` renders `<Card>`, `<Card>` renders `<Pill>`, etc.

## Prerequisites

- **Node.js LTS** — pinned via `.nvmrc`. Run `nvm use` before working.
- **`sqlite3` CLI** — used by `baluarte-remember`.
- **OAuth-authenticated Metalab MCP** — `mcp__metalab__figma__*` and `mcp__metalab__figma_live_*` must be reachable.

## Typical loop

```
# 1. Sync the Figma file into the registry
/baluarte-analyze https://www.figma.com/design/<key>/<name>

# 2. Generate / refresh the Storybook artifacts
/baluarte-build                       # everything
/baluarte-build --scope components    # subset
/baluarte-build --name Card           # one row

# 3. Open Storybook
cd baluarte-app && npm run storybook
```

`baluarte-analyze` is idempotent — re-running it after design changes diffs the file by `content_diff_hash` (SHA-256 over each artboard's deep node tree) and writes the minimum delta.

`baluarte-build` is also incremental — it parses the existing `.tsx` / `.stories.tsx` artifacts, computes a field-level diff against the registry, and patches in place. Files that lack the `// AUTO-GENERATED by baluarte-build` header are never overwritten.

## Where data lives

- **SQLite registry**: `.data/baluarte.db` (gitignored). Schema source of truth: `.claude/skills/baluarte-remember/schema.sql`. Rebuild:
  ```bash
  rm -f .data/baluarte.db* && mkdir -p .data && sqlite3 .data/baluarte.db < .claude/skills/baluarte-remember/schema.sql
  ```
  Tables — 7 single (`pages`, `storybook`, `layouts`, `components`, `states`, `figma_nodes`, `properties`) + 1 variant (`component_variants`) + 5 relationship (`pages_registry`, `layout_registry`, `layout_properties`, `components_registry`, `components_properties`). `states` is pre-seeded with the six allowed values.

  Each entity in `layouts`/`components` carries one re-sync signal: **`content_diff_hash`** (SHA-256 of the deep node tree returned by the Figma MCP). The Figma API does not expose a per-node `lastModified`, so we hash the fetched JSON instead. Any structural or styling change to the artboard (or its descendants) flips the hash and triggers a re-sync.

- **Reusable SQL**: `/queries/*.sql`, indexed in `/queries/INDEX.md`. Every SQL operation `baluarte-remember` runs comes from a file there. New operations get a new `.sql` file + INDEX row — never inline SQL for anything that recurs.

- **React + Storybook code**: `baluarte-app/src/layouts/<Name>/` and `baluarte-app/src/components/<Name>/`. Tailwind theme sidecar at `baluarte-app/baluarte.tailwind.ts` (regenerated whole by `baluarte-build`, imported by `baluarte-app/tailwind.config.ts`).

- **Skills source of truth**: `.claude/skills/<skill-name>/SKILL.md`. The `.claude/` directory is checked into git.

## Persistence rules

- Anything queryable / row-shaped → `baluarte-remember` (SQLite).
- Anything prose-shaped (preferences, status, decisions) → `MEMORY.md` (Claude's auto-loaded memory).
- **Never write SQL outside the `baluarte-remember` skill.** If a new operation is needed, add a new `/queries/<verb>_<table>.sql` file (with `:bound_params`), register it in `/queries/INDEX.md`, and update `schema.sql` if the table itself needs to change.
- **All SQL runs via bash `sqlite3`.** Python is forbidden; `node:sqlite` is forbidden.
- **All Figma access is via the Metalab MCP tools.** The REST API is not called directly.
