# baluarte-build-properties

Reads every row in `visual_properties` and emits a single fully-regenerated `baluarte-app/baluarte.tailwind.ts`. The sidecar is imported by `tailwind.config.ts` (set up by `baluarte-build-setup`), so updates flow directly into Tailwind classes used by every component and layout.

## Tool access for this skill

- Filesystem (`Read`, `Write`, `Edit`).
- `Bash` (sqlite3, sha256sum).
- `baluarte-remember` (read + write).
- **No Figma MCP access.**

## Required arguments

None.

## Optional arguments

- `--prompt "<free-form context>"` — user-supplied guidance. Use it to:
  - Pin a specific Tailwind key ordering or grouping convention (e.g. `--prompt "group brand colors above neutrals"`).
  - Add a comment header to the generated file (e.g. `--prompt "add a // Source: design-system v3 header"`).
  - Force-skip rows you don't want in the sidecar yet (e.g. `--prompt "skip every row whose name starts with 'experimental/'"`). The skill still leaves the rows in SQLite — it just omits them from this pass.

## Pre-checks

1. **`baluarte-app` is set up.** `baluarte-app/baluarte.tailwind.ts` and `baluarte-app/tailwind.config.ts` must exist. If missing → fail with: "Run `baluarte-build-setup` first."
2. **Read every property** ordered for stable diffs:
   ```bash
   sqlite3 -header .data/baluarte.db <<'SQL' > /tmp/baluarte.props.tsv
   .mode tabs
   SELECT uuid, name, type, tailwind_name, css_property, value, source_hash
   FROM visual_properties
   ORDER BY type, tailwind_name;
   SQL
   ```

## Map property `type` → Tailwind theme key

```
color      → colors
spacing    → spacing
sizing     → spacing       (Tailwind shares the `spacing` scale across width/height/padding)
radius     → borderRadius
shadow     → boxShadow
typography → split: fontFamily / fontSize / fontWeight / lineHeight
            (one visual_property entry can populate multiple keys; see typography rule below)
other      → emit a comment-only line under a top-level `_other` key — not active in Tailwind
            but kept so audit queries can confirm it was processed
```

For `typography`, parse the row's `value` (a JSON blob `{ family, weight, size, lineHeight }`) and emit:
- `fontFamily.<tailwind_name>: [family]`
- `fontSize.<tailwind_name>: [size, { lineHeight }]` (Tailwind's tuple form)
- `fontWeight.<tailwind_name>: weight` (only if explicit)

## Generate `baluarte.tailwind.ts`

Always **fully overwrite** the file. Do not Edit / patch it. The skill is the only writer — hand edits will be lost (this is documented in the file header).

```ts
// AUTO-GENERATED by baluarte-build-properties — do not hand-edit.
// Source: SQLite visual_properties. Re-run the skill to regenerate.

export const baluarteTheme = {
  colors: {
    'brand-primary': '#0F62FE', // @baluarte uuid=<UUID>
    'surface-default': '#FFFFFF', // @baluarte uuid=<UUID>
  },
  spacing: {
    'md': '16px', // @baluarte uuid=<UUID>
  },
  borderRadius: {
    'md': '8px', // @baluarte uuid=<UUID>
  },
  fontFamily: {
    'heading': ['Inter', 'sans-serif'], // @baluarte uuid=<UUID>
  },
  fontSize: {
    'heading-lg': ['32px', { lineHeight: '40px' }], // @baluarte uuid=<UUID>
  },
  boxShadow: {
    'card': '0 1px 2px rgba(0,0,0,0.04), 0 4px 8px rgba(0,0,0,0.04)', // @baluarte uuid=<UUID>
  },
} as const;
```

Emit empty objects for keys with no rows so the file shape is stable. Always emit the same top-level keys in the same order: `colors`, `spacing`, `borderRadius`, `fontFamily`, `fontSize`, `fontWeight`, `lineHeight`, `boxShadow`, `_other`.

The `// @baluarte uuid=<UUID>` marker is the source of traceability. Future iterations of this skill (or other tooling) can grep it to associate Tailwind entries back to a SQLite row.

## Verify the wiring

`tailwind.config.ts` must `import { baluarteTheme } from './baluarte.tailwind'` and spread it into `theme.extend`. `baluarte-build-setup` writes this; this skill does not modify `tailwind.config.ts`. If the import is missing (user removed it), fail with a clear message listing what to add back.

## Persist per-row state

After a successful write, update each `visual_properties` row:

```bash
# For each row, compute the hash of `value` and stamp it.
sqlite3 .data/baluarte.db <<'SQL'
UPDATE visual_properties
SET source_hash = (
  SELECT lower(hex(randomblob(0)))   -- placeholder; computed in shell, see below
);
SQL
```

In practice the hash is computed in shell because SQLite has no native SHA-256:

```bash
while IFS=$'\t' read -r uuid name type tailwind_name css_property value source_hash; do
  HASH=$(printf '%s' "$value" | sha256sum | awk '{print $1}')
  sqlite3 .data/baluarte.db \
    "UPDATE visual_properties
     SET source_hash='$HASH', applied_to_tailwind_at=datetime('now')
     WHERE uuid='$uuid';"
done < <(tail -n +2 /tmp/baluarte.props.tsv)
```

(`tail -n +2` skips the SQLite header row.)

## Drift query (run before and after for visibility)

```bash
sqlite3 -header -box .data/baluarte.db \
  "SELECT name, type, tailwind_name,
          CASE WHEN applied_to_tailwind_at IS NULL THEN 'never-applied'
               WHEN source_hash IS NULL            THEN 'never-applied'
               ELSE 'applied'
          END AS status
   FROM visual_properties
   ORDER BY status, type, tailwind_name;"
```

After a successful run, every row should be `applied`. If something is still `never-applied`, the row's `value` was probably empty or its type was unrecognised — log and continue.

## Smoke check

```bash
cd baluarte-app && npx tsc --noEmit
```

If the regenerated file has TypeScript errors (most commonly: an invalid value for `fontSize` tuple), the skill rolls back by writing a minimal-but-valid `baluarteTheme` and surfaces the offending property uuid for the user to fix in SQLite.

## Hard rules

- This skill is the **only** writer of `baluarte-app/baluarte.tailwind.ts`. Always full-rewrite.
- **Never call another baluarte-* skill** other than `baluarte-remember`.
- Never modify `tailwind.config.ts`. If the import is missing, fail with instructions.
- Never call Figma MCP.
- Always update `source_hash` and `applied_to_tailwind_at` for every row processed.
- Never write outside `baluarte-app/`.
- Property `value`s already in canonical form (hex, px, JSON for typography). If a row is malformed, log it and skip — do not invent values.
